# 设计文档编写约束

> 目标:统一 `design/` 目录下所有文档的定位、结构和编写方式,让每一篇 module 文档都既是设计规范,也是后续工程实现与 AI 执行的约束文档。

## 1. 文档定位

`design/` 下的文档不是讨论稿,也不是会议纪要。统一定义为:

- module 级设计文档
- harness engineering 风格文档
- 设计规范与执行约束并重的正式文档

每篇文档必须回答两类问题:

- 这个 module 应该如何设计
- 工程师或 AI 后续可以怎么改、不能怎么改

## 2. 适用范围

适用于 `design/` 目录下除 `_index.md` 以外的所有 module 文档。

不适用于:

- 过程性讨论记录
- 会议纪要
- 项目进展跟踪
- 临时草稿和未收敛结论

这类内容不应直接进入 `design/` 的正式 module 文档主体,改写到 `系统/灵光捕手.md` 或临时 working doc。

## 3. 核心原则

- 先定义边界,再定义细节
- 先写稳定约束,再写实现建议
- 先写禁止项,再谈扩展方式
- 结论必须可执行,不能只停留在讨论层
- 文档必须能约束人,也能约束 AI
- 文档应优先服务长期一致性,而不是一次性表达完整想法

## 4. 统一文档模板

每篇 module 文档原则上应包含以下章节:

### 4.1 模块目标

写清楚该 module 要解决什么问题、为什么存在、服务什么系统目标。

### 4.2 边界与职责

- 该 module 管什么
- 不管什么
- 与相邻 module 的边界在哪

### 4.3 核心对象 / 输入输出

核心对象、输入、输出、关键引用关系。Schema 类文档必须明确最小字段集合。

### 4.4 结构规则

- 字段、状态、约束、不变量
- 命名规则
- 单选 / 多选 / 是否可空

### 4.5 执行约束

- 可以改什么
- 修改前必须先看什么文档
- 哪些变更必须同步更新上下游
- 哪些操作不能绕过现有规则

### 4.6 禁止项

- 模糊词替代结构定义
- 只写结论不写边界
- 新增字段却不说明兼容与迁移
- AI 直接改受人工维护约束的数据源

### 4.7 扩展方式

未来扩字段、改结构、补流程、接数据库或接页面应按什么方式演进。

### 4.8 关联文档

- 上位规则文档
- 上游约束文档
- 下游实现文档
- 全局大纲中的对应任务项

## 5. 编写规则

- 标题直指 module,不用口语化标题
- 文档名表达模块对象和主题,不用模糊命名
- 同一概念在不同文档中保持同名(术语表见根 `CLAUDE.md`)
- 必须区分"已定规则""建议方案""待定项",待定项标 `TBD`
- 必须显式标注单向约束和双向依赖
- 必须优先写稳定约束,不先写页面表现或示例描述
- 示例只能用于辅助理解,不能替代正式规则
- 文档中的规则应尽量可被后续程序、页面或 AI 检查

## 6. 执行约束

任何人或 AI 修改 `design/` 文档时:

- 先读本文件,再修改具体 module 文档
- 变更影响模块边界 → 同步更新 `02-项目看板系统全局设计大纲.md`
- 变更影响共享概念 → 同步检查相关 module 文档
- 讨论未收敛 → 不写入正式规则区,用 `TBD` 标记
- 新增 module 文档 → 遵守本文件统一模板,并在 `_index.md` 与 `CLAUDE.md` 登记
- 已有文档结构不符约束 → 先补齐结构再扩内容

## 7. 禁止项

- 把设计文档写成聊天记录
- 把设计文档写成纯结论清单
- 关键约束散落多处但没有主文档
- 用"先这样""大概""后面再说"代替正式约束
- 写了字段名但不说明语义和边界
- 写了页面方案但不对应底层数据结构
- 写了执行要求但不说明约束对象和触发条件

## 8. 文档关系

- `01-设计文档编写约束.md` — 所有 module 文档的上位编写规则
- `_index.md` — 目录入口与导航
- `02-项目看板系统全局设计大纲.md` — 全局任务索引、状态总览、文档映射入口
- 其他 module 文档 — 具体模块的设计规范与执行约束载体

## 9. 对全局大纲的要求

`02-项目看板系统全局设计大纲.md` 仅承担:

- 全局任务列表
- 模块文档映射
- 当前状态追踪
- 推荐推进顺序

具体约束下沉到对应 module 文档,不在大纲承载细节。

## 10. 新文档命名

- 偏总原则与长期稳定规则 → `xxx规范.md`
- 偏 module 行为边界和工程约束 → `xxx约束.md`
- 偏具体结构设计且承担执行规则 → `xxxSchema约束.md` 或 `xxx设计.md`
