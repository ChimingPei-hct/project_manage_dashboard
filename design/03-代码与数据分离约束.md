# 代码与数据分离约束

## 1. 模块目标

确保**代码 / 配置 / 实例真实数据**三者解耦:

- 代码升级不会污染实例数据
- 实例数据增长不会被推入代码仓库
- 多实例(如不同 PDT 共用一套代码)可独立维护各自数据,互不干扰
- AI 操作时清楚知道"该改 main 还是数据分支",避免误写

本约束直接参考 `oversea_projects` v3.0.0+ 的"代码与数据分离"实践。

## 2. 边界与职责

### 本约束管什么

- main 分支与 data 分支的职责划分
- worktree 挂载方式与运行时数据目录
- main 分支允许出现什么数据(只允许空模板)
- DATA_DIR 环境变量的传递与生效

### 不管什么

- 数据 schema 本身(归 `06`–`09`)
- 权限模型(归 `10`)
- 后端如何读写数据文件(归 `11`)

## 3. 分支模型

### 3.1 main 分支

- 内容:**代码 + 约束文档(design/) + 空模板数据**
- `design/*.json` 必须是空模板(`[]` 或 `{}`),`design/*.jsonl` 必须是空文件
- `design/weekly_snapshots/` 必须为空目录(或仅含 `.gitkeep`)
- 任何提交到 main 的 PR 必须经 `validate_data_files.py --template-mode` 校验通过

### 3.2 data 分支

- 命名:`data-<instance_name>`(如 `data-multicam-pilot`、`data-as33-pilot`)
- 每个数据分支对应**一个部署实例**
- 不存代码,只存 `design/` 下的运行时数据文件 + `config.json`
- 通过 `git worktree add <path> data-<name>` 挂载到独立工作目录

### 3.3 worktree 布局示例

```
/Users/xxx/repos/project_manage_dashboard          # main, 代码
/srv/pmd-instances/multicam-pilot                  # worktree, data-multicam-pilot
/srv/pmd-instances/as33-pilot                      # worktree, data-as33-pilot
```

后端启动时:`DATA_DIR=/srv/pmd-instances/multicam-pilot/design uvicorn main:app ...`

## 4. 运行时数据目录(DATA_DIR)

### 4.1 后端读取规则

- 启动必读环境变量 `DATA_DIR`(指向一个 `design/` 目录的绝对路径)
- 未设 `DATA_DIR` 时,**仅本地 dev 场景**回退到仓库内 `./design`;生产部署必须显式传入
- 所有数据文件读写一律走 `Path(DATA_DIR) / "<file>"`,严禁硬编码相对路径

### 4.2 config.json

每个 data 分支的 `design/config.json` 必填:

```json
{
  "instance_name": "multicam-pilot",
  "port": 18080,
  "pdt_default_name": "Multicam Pilot 3.0",
  "feishu_app_id": "cli_xxx",
  "allowed_tenant_keys": ["xxx"],
  "site_url": "https://pmd-multicam.internal/"
}
```

- `feishu_app_secret` **不写入 config.json**,通过环境变量 `FEISHU_APP_SECRET` 注入(回退别名 `LARK_APP_SECRET`,见 `11 §6.1`)
- `feishu_app_id` 可放 `config.json`,但环境变量 `FEISHU_APP_ID` / `LARK_APP_ID` 优先
- `allowed_tenant_keys` 列表,登录后校验 `tenant_key` 是否在内;空数组 = 不限制
- `port` 用于 `start-instance.sh` 启动 uvicorn
- 多实例端口必须互不冲突

### 4.1 特例 — 首个 PDT 实例(Luna 6,2026-05-23 起)

- 当前 main 分支**额外承载 Luna 6 PDT 真实数据**(`pdt.json`/`ltcs.json`/`modules.json`/`module_status.json`/`user_registry.json` + `assets/luna-6/` 图标资源),不再保持空模板
- 额外允许 `categories.json` 入 main:用途为 LTC 模板池(`scope=ltc_template`)的全 PDT 共享 seed,与 `modules.json` 中 `scope=ltc_template` 项目对齐;通过顶栏齿轮 → PDT 配置 → LTC 模板 Tab 编辑(详见 `13 §6.0`)
- **严禁入 main**:`module_updates.jsonl`(历史流追加日志,纯实例数据)、`weekly_snapshots/*.json`(周快照实例数据)— 即使开发期也必须走 data 分支
- 原因:单 PDT 部署期,无多实例需求;直接在 main 维护 Luna 6 数据更便于演示与协作开发,经用户授权破例
- 引入第二个 PDT 实例时,必须把 Luna 6 数据迁回 `data-luna6` 分支 worktree,main 恢复空模板规则
- 校验脚本 `validate_data_files.py --template-mode` 与 pre-commit 钩子在过渡期对上述 6 个文件放行(白名单),其余文件仍按空模板校验

## 5. 空模板规则(main 分支必守)

| 文件 | 模板值 |
|------|--------|
| `pdt.json` | `{}` |
| `ltcs.json` | `[]` |
| `modules.json` | `[]` |
| `module_status.json` | `{}` |
| `module_updates.jsonl` | 空文件 |
| `weekly_snapshots/` | 空目录(允许保留 `.gitkeep`) |
| `super_admins.json` | `[]` |
| `pdt_admins.json` | `[]` |
| `ltc_admins.json` | `{}` |
| `user_registry.json` | `[]` |
| `config.json` | 模板范本(占位字段值如 `"<instance_name>"`) |
| `contact_cache.json` | 可保留共享数据,各实例间可继承 |
| `assets/<pdt-code>/` | 空目录 | 每实例的二进制资源(PDT 图标等);文件随 data 分支走,main 空 |

## 6. 执行约束

### 6.1 修改数据时

- **只动 data 分支的 worktree 目录,绝不动 main 上的 `design/*.json`**
- main 上的 `design/*.json` 出现任何非空内容 = 违规,必须立即清空回模板

### 6.2 修改代码/约束文档时

- **只动 main**
- 不允许在 data 分支提交代码或修改 design/ 下的 md 约束文档(那些只在 main 维护)

### 6.3 新建部署实例的标准流程

```bash
# 1. 在 main 上拉数据分支
git checkout -b data-<name>
# 2. 填入 config.json / super_admins.json
# 3. 推送数据分支
git push -u origin data-<name>
# 4. 在部署机上挂载 worktree
git worktree add /srv/pmd-instances/<name> data-<name>
# 5. 启动
DATA_DIR=/srv/pmd-instances/<name>/design \
FEISHU_APP_SECRET=xxx \
bash app/backend/start-instance.sh
```

### 6.4 服务器运行目录禁忌

- **禁止在运行中实例的 worktree 目录切分支** — 会破坏数据一致性
- 升级代码:在 main worktree 上 `git pull` 然后重启所有实例服务,**不需要**在 data worktree 上 pull
- 数据迁移:在 data worktree 上做修改 + commit + push,不动 main

## 7. 禁止项

- **禁止在 main 写入真实数据** — 包括"我先存一份样例数据看看效果"
- **禁止把 `.venv/`、`node_modules/`、`dist/` 写入任何分支**(必须 gitignore)
- **禁止把 `FEISHU_APP_SECRET`、JWT secret 等密钥写入任何分支**(走 env / 单独 secret 文件且 gitignore)
- **禁止跨分支 cherry-pick 数据**(数据有实例语义,跨实例 cherry-pick 几乎肯定语义错乱)
- **禁止在 data 分支上修改代码**

## 8. 校验与防护

- `.githooks/pre-commit`:main 分支拦截 `design/*.json`、`design/*.jsonl`、`design/weekly_snapshots/` 的任何 Add/Modify/Rename;在仓库根执行 `git config core.hooksPath .githooks` 启用(已在 Phase 8.3 落地并配置)
- (TBD)`validate_data_files.py`:main 模式下断言所有数据文件为空模板;待与 schema 校验合并实现
- (TBD)CI 上跑同一脚本作为冗余防线

## 9. 扩展方式

- 未来若改用数据库(SQLite/Postgres):`DATA_DIR` 改指数据库连接字符串(或新增 `DATABASE_URL`),JSON 文件作为初始化导入的种子;本约束的"分支隔离"思想保留(每实例独立 DB)
- 未来若多实例共享某些只读数据(如 `contact_cache.json`),可拉单独的 `data-shared` 分支并以软链方式挂入实例 worktree
