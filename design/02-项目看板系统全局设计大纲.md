# 项目看板系统全局设计大纲

## 1. 模块目标

PMD(Project Manage Dashboard)是面向**单个产品线(PDT)及其下属若干子项目(LTC)**的状态看板系统,把"周报 PPT"形态的项目状态固化为可在线协作、可历史回溯、可权限隔离的 Web 系统:

- 各模块负责人(Module Owner)每周维护自己模块的红/黄/绿状态与风险说明
- PDT 管理者实时看到产品线总览、各 LTC 研发进展、风险下钻
- 周快照固化每周状态,支持历史对比

## 2. 系统边界

### 系统管什么

- PDT 信息、里程碑、产品线级总览模块
- LTC 列表与每个 LTC 下的研发模块/子项配置
- 模块状态(色块 + KPI + 风险说明)的填报与展示
- 周快照冻结与历史回放
- 用户角色与权限(Super / PDT Admin / LTC Admin / Owner / 访客)

### 系统不管什么

- 详细任务管理(任务级别归 Jira/禅道等)
- 文档管理、知识库
- 实时通讯(评论可后续扩展,但不是 v1 范围)
- 代码托管、CI/CD
- 报销、人力等非项目管理职能

## 3. 部署模型

- **单部署实例 = 单 PDT + 多 LTC**
- 一个 PDT 想要独立看板就部署一个实例;多 PDT 各自实例隔离
- main 分支只放代码与空模板;实例真实数据走独立 data 分支 + git worktree(详见 `03-代码与数据分离约束.md`)

## 4. 核心概念(术语表)

| 术语 | 定义 |
|------|------|
| **PDT** | Product Development Team — 产品线,单实例唯一 |
| **LTC** | Lead-to-Cash 子项目,PDT 下的独立交付项目 |
| **Module** | 看板基本单元,`scope=pdt` 为 PDT 级总览卡片,`scope=ltc` 为某 LTC 下的子模块 |
| **Sub-item** | LTC 模块下的色块子项(如"MCU 底软"模块下的 Autosar BSW、RTE 等) |
| **Owner** | 模块负责人,负责维护本模块状态 |
| **Status** | 模块当前态:`module_color` + 可选 `sub_items_color` + 可选 `kpi_values` + 可选 `risk_note` |
| **Snapshot** | 周快照,某周冻结的全量 `module_status` |

## 5. 数据分层(三层分离)

| 层 | 文件 | 性质 |
|----|------|------|
| **配置层** | `modules.json`、`ltcs.json`、`pdt.json` | 谁负责什么,结构性 |
| **当前态层** | `module_status.json` | 此刻状态,被频繁覆写 |
| **历史层** | `module_updates.jsonl` + `weekly_snapshots/*.json` | 不可改写,append-only / 冻结只读 |

**为何分离**:配置变更(增删模块、改 Owner)不污染状态历史;状态高频写不污染配置;周快照与历史流互不替代(流是细粒度事件,快照是周粒度的一致性视图)。

## 6. 全局推进顺序与 v1 目标

### v1 完成标准

- [ ] main 分支可被 fork 出空白实例(走 data 分支),5 分钟内启动可访问
- [ ] Super Admin 能配置 PDT 名、里程碑、LTC 列表、模块树、Owner 绑定
- [ ] Module Owner 能填报本模块状态(色块 + 风险说明 + KPI)
- [ ] 三类查看页面可视:PDT 总览 / LTC 研发进展 / 风险详情
- [ ] 周快照可手动冻结,前端可切换历史周回看
- [ ] 角色权限矩阵测试全绿
