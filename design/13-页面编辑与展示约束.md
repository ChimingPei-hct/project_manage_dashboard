# 页面编辑与展示约束

## 1. 模块目标

定义四类正式页面的展示主信息、编辑入口、跳转关系,确保管理者一眼可读、Owner 一键可填、风险一处可下钻。

## 2. 页面清单

| 页面 | 视图标识 | 主用户 | 数据来源 |
|------|---------|--------|---------|
| PDT 总览 | `?view=pdt` | 管理者(全员可看) | scope=pdt 模块 + pdt.milestones |
| LTC 主页 | `?view=ltc&id=<ltc_id>` | LTC Admin / Owner / 管理者 | scope=ltc_template ∪ (scope=ltc & ltc_id=当前) + `ltcs[i].milestones` |
| LTC 主页 · 风险区锚点 | `?view=risks&id=<ltc_id>`(`risk` 别名) | 管理者 / 评审会议 | 同上,载入 LTC 主页后自动滚动到 `#risk-section` |

> **LTC 主页是单页面**:左侧 PDT→LTC 树常驻,右侧单列上下滚,从上到下依次为 LTC 里程碑时间轴、看板区(全部模块)、风险详情区(只渲染非绿模块)。`?view=risks` 不再渲染独立组件,而是定位到同一页面的风险区锚点。

> **管理后台已退役**(原 `?view=admin` 的树+抽屉形态)。所有配置入口下沉到 PDT 总览 / LTC 主页的右上工具栏,顶栏齿轮承载 **PDT 级配置**(名称/图标 + LTC 模板池),其它配置入口都在就地工具栏。详见 §3.3 / §4.4 / §6。

### 2.1 URL 参数约定

- LTC 实体 id 统一走 `?id=<ltc_id>`;旧链接 `?ltc=<ltc_id>` 由 `useView.js` 兼容解析
- `?view=risk`(单数)是 `?view=risks`(复数)的别名,在 `useView.js::VIEW_ALIAS` 注册;两者等价。两者均渲染 `LtcMain.vue`,后者额外携带 `scrollTo='risk-section'` 行为
- 未知 `view` 值(含历史遗留的 `?view=admin`)回退到 `pdt`(默认视图);`?node=` 参数已废弃,不再解析
- `?sub=timeline|kanban` 是 PDT 总览页的二级 tab;缺省 / 未知值回退到 `timeline`(其他页忽略该参数)

## 3. PDT 总览

### 3.1 布局(对应 `datas/screenshot-20260522-194954.png`)

- **顶栏品牌名**:左上 logo 文字 = `pdt.name`(动态),未加载到 PDT 时回退到字符串 `PMD`。**编辑入口** = 顶栏右侧齿轮(⚙)按钮 → `PdtConfigDrawer`(只含 PDT 名称字段;保存后通过 `useDashboard.refresh()` 联动顶栏)
- **页头**:展示 `StatusLegend` + admin 快捷工具按钮(🗓 里程碑 / ⚙ 权限管理 / 📸 快照)
- **二级 Tab**:`时间线` / `全局看板` 两个并列按钮,通过 `?sub=timeline|kanban` 在 `useView.js` 内驱动;默认值 `timeline`。`时间线` 视图渲染 `TimelineBar`,`全局看板` 视图渲染 PDT 卡片网格(含空态提示)。两个视图同一时间只显示一个。**代码符号(组件名 `TimelineBar`、URL 参数 `sub=timeline`、数据字段 `milestones`)保持不变**,只统一用户可见文案
- **时间线视图**:`TimelineBar`,横向时间线,基于 `vis-timeline`(MIT,直接引入,不再自研几何排版)
  - 数据源:`pdt.milestones`;按 `date` 升序
  - 顶部为日期轴(年/月双层),下方按 `type` 分行(每个出现的 type 占一行,如 TR/SOP/OTA/目标/...)
  - 每个里程碑渲染为「形状 + 名字 + 月日」:形状/颜色来自 `04-PDT与LTC管理规范.md` 的 type 约定表;未列类型降级灰色圆点
  - 同行同日期自动错位堆叠,无须前端手算
  - 自带「今天」竖线、鼠标滚轮缩放、拖动平移;默认窗口覆盖最早→最晚里程碑 + 左右各 8% 留白
  - XSS 防护:vis-timeline 默认过滤 HTML 属性,自定义内容必须用 `template` 函数返回 DOM 元素,**严禁拼字符串带 class/style**
- **全局看板视图**:scope=pdt 模块按 `group` 分组,每组若干卡片;一行 4 列响应式
- 每卡片:
  - 标题:模块名 + 整体状态灯(`module_color`)
  - 状态灯 dots 顺序为 **绿-黄-红**(左→右,green-yellow-red),由 `ModuleStatusDots` 统一控制
  - "关键目标" 与 "重点问题" 两个区段标题**恒显**,空数据时显示 "暂无" 灰字占位
  - 主体:`kpi_items` 每条渲染为「目标 / 现状」两行堆叠,组级灯挂在**目标行右端**(与卡头右侧 ModuleStatusDots 最右一颗灯对齐)
  - 底部:风险说明摘要(若非绿)+ Owner 名 + 最近更新时间
- 卡片右上角:edit 图标(仅 Owner/PDT Admin 可见),点击进入 StatusCell 编辑
- **视觉风格(样板 B · Report 体)**:
  - 标题字体使用衬线(`Source Han Serif SC / Songti SC` fallback),17px、Semibold、字距 1px
  - 卡头与卡脚使用 `1px solid var(--text)` 实线分隔(汇报体)
  - 区段标签**只显示中文**:左侧 `关键目标` / `重点问题` 衬线中文(letter-spacing 4px),下方 `1px solid var(--border-subtle)`;不再显示英文 `KPI` / `ISSUES · N`
  - KPI 渲染为"目标 / 现状"两行堆叠的组列表:每组上一行 `目标` 标签 + dim 灰文本 + **右端 `kpi-dot`**(green/yellow/red,未填渲染为 gray 占位 — 灯位恒显,不允许隐藏),下一行 `现状` 标签 + 强调文本(`color: var(--text-primary); font-weight: 600`);组间 `1px dashed var(--border-subtle)` 分隔,最后一组无边
  - 重点问题用 `<ul>`,每行左侧 5px 小圆点指示 severity(灰/黄/红),行间 `1px dotted`
  - 数字与英文走 `font-feature-settings: 'tnum' on`,中文与衬线英文标题对比突显汇报物气质
  - 样板选样源文件:`doc/card-style-samples/sample-B-report.html`

### 3.2 主信息

- 必须显式展示的信息:模块名、状态灯、Owner、最近更新时间
- KPI 缺失时显示占位 "— —" 而非空白
- 风险说明截断 2 行 + "展开"

### 3.3 编辑入口

PDT 总览页采用"看 = 编"原则,所有 PDT 相关配置都在本页就地完成,不再跳后台。

**看板卡片**统一由 `ModuleCardGrid.vue` 渲染(harness 红线,LTC 看板复用同一组件,见 §4 与 §9)。本节描述的是该组件打开的编辑弹窗。

**编辑弹窗 `StatusEditDialog` 的三块布局**(`ModuleCardGrid` / `ModuleRiskList` 共用):

1. **基本信息**(顶部高亮区)
   - 卡名 / Owner —— 仅 `canEditStructure=true` 可改,否则只读展示(`group` 字段后端兼容保留,默认 `总览`,UI 不再暴露)
   - 整体状态灯(`module_color`)3 色 swatch(绿/黄/红;`gray=未填报` 仅由系统初始化,弹窗不提供手动设置) —— 所有 `editable` 都能改
   - 「🗑 删除该卡」放在本块右下角,仅 `canEditStructure=true && mode==='edit'` 可见,走 ConfirmDialog → `DELETE /api/modules/{id}` → 本地 splice
2. **关键目标** —— 列表,每行 = 一个 `kpi_items[i]`,字段 `{goal, actual, color}`(自由文本,不再切分 label/value/单位)
   - 行内三栏:`目标` 多行文本输入 / `现状` 多行文本输入 / 灯下拉(— / 🟢 绿 / 🟡 黄 / 🔴 红)+ 右侧「×」删除按钮
   - 旧字段 `label/value/target` 由后端读侧透明映射,UI 不暴露
   - 增删行控件「+ 加目标」:仅 `canEditStructure=true`(Owner 只能改文本与灯,不能改行数)
   - 保存过滤:`goal` 与 `actual` 都为空的行丢弃
3. **风险/重点问题** —— 列表
   - 每行一个 `<textarea>`,**弹窗里不再有 severity 下拉**;新增风险统一 `severity='red'`,看板正面圆点渲染按 severity 着色仍兼容旧数据
   - 「+ 风险」按钮在块标题右侧
   - 风险列表允许为空(非绿状态也不强制要求)

**子项色块**(`sub_items`)块**已统一移除**(LTC 卡也已对齐为「基本/KPI/风险」三块);后端字段仍保留兼容老数据,但弹窗 UI 不再暴露增删与色块编辑。

**一键保存**:弹窗底部单按钮:
- `mode='edit'`:`保存` —— 一次性提交;status 字段走 `PUT /api/status/{id}`,structure 字段(name/group/owner)若 `canEditStructure=true && dirty` 同步走 `PUT /api/modules/{id}` 并本地原位替换 `modules[idx]`
- `mode='create'`:`创建` —— 只校验卡名非空,`POST /api/modules` 后 push 进本地 `modules`

**权限分层**(镜像后端 `can_edit_module_status` 与 PDT Admin 判定):

- `editable`(Owner / PDT Admin / Super):可改 整体灯 / KPI 行的"目标"、"现状"、"灯" / 风险列表;入口由前端 composable `useEditableModules` 决定
- `canEditStructure`(仅 Super / PDT Admin):额外可改 卡名 / Owner;可增删 KPI 行;可删除该卡
- 历史周(`useDashboard.isReadonly=true`)下 `editableSet` 强制清空,所有入口隐藏/禁用
- 422 inline 渲染在弹窗错误条;403 用弹窗内 toast 提示「无权编辑此模块」

**新增卡片**(仅 Super / PDT Admin 可见):

- 看板网格末尾追加一张虚线「+ 新增卡片」占位卡(`.add-card`),与其他卡同尺寸
- 点击复用 `StatusEditDialog` 的 `mode='create'` 形态,**字段集合与 `mode='edit'` 一致**(基本信息 / 整体状态灯 / 关键目标 / 风险),仅"删除该卡"按钮在 create 模式隐藏
- 提交链路为前端**串联两接口**:先 `POST /api/modules` 创建结构(scope 由当前页面隐式决定,不在弹框暴露),返回后 push 进本地 `modules`;若用户填了 KPI / 风险 / 非灰整体色,继续 `PUT /api/status/{key}` 写入状态。第二步失败不回滚,弹框内 toast 提示「卡片已创建,状态未保存,请打开编辑补填」
- 标题与主按钮文案随 mode 切换:`新建 PDT 卡片 / 模块名` + `创建 / 保存`

**顶部工具区**(`.head` 右侧,仅 Super / PDT Admin 可见,只读周隐藏):

- 「🗓 时间线管理」→ `window.open('?view=milestones', '_blank')` 在新标签页打开独立的 `MilestonesDrawer` 页面(便于一边看时间线一边编辑);**不再用 Modal 内联**
- 「⚙ 权限管理」→ Modal 包 `AdminPerms`
- 「📸 快照」→ Modal 包 `SnapshotPanel`

> 历史上的「👥 人员」入口及 `AdminUsers` 组件已下线;人员/角色绑定统一在「⚙ 权限管理」内维护,不再单独保留管理员名册抽屉。

> 历史上的「🧩 总览卡片」入口及 `OverviewCardsDrawer` 已下线;PDT 总览卡片的新增 / 排序 / 进入模块详情统一在看板网格内就地完成(末尾 dashed 「+ 新增卡片」 + 卡头三圆点 / 编辑按钮 → `StatusEditDialog`)。新增二级 Modal `ModuleDrawer` 入口须挂在看板内,严禁恢复抽屉式总览卡片管理页。

**子 Tab 可见性收敛**:
- `?sub=timeline`(时间线视图):工具区**仅显示「🗓 时间线管理」**,隐藏权限管理 / 快照两个按钮(避免在时间线场景误入与该视图无关的配置)
- `?sub=kanban`(全局看板视图):三个按钮全部显示

**独立时间线管理页**:`?view=milestones` 由 `App.vue` 的 `viewComp` switch 路由到 `MilestonesDrawer`,作为顶层主页面渲染,不嵌套在 PDT 总览内;关闭即关闭浏览器标签页,原 PDT 总览页不受影响。**该页只渲染编辑表格,不再叠加时间线预览**(`MilestoneEditor` 已删除 `showPreview` prop 与对应预览块,需要看效果回原 tab 看)。

**时间线节点类型样式单一来源**:
- 类型 → 形状/颜色/中文标签映射统一定义在 `app/frontend/src/constants/milestoneTypes.js` 的 `TYPE_STYLE`
- `TimelineBar.vue` 与 `MilestoneEditor.vue` 必须从该模块 import `TYPE_STYLE` / `TYPE_OPTIONS` / `styleOf`,**禁止在组件内拷贝**
- 正式类型 7 种:`TR / SOP / OTA / review / goal / Block / other`;未知值(含历史 `Custom`)按 `other` 灰色圆点降级渲染
- `MilestoneEditor` 的类型下拉每个 option 文本格式 `{shape} {key} · {label}`(如 `△ TR · TR`),选中后 select 右侧渲染对应形状字符,颜色取自映射

**PDT 名称**:不在本工具区,移到顶栏齿轮(`App.vue` → `PdtConfigDrawer`);此处不再放「⚙ PDT 基础」按钮。

**时间线编辑入口**:

- `?sub=timeline` 视图内**不再内联** `MilestoneEditor`;所有编辑统一走「🗓 时间线管理」按钮 → 新标签页 `?view=milestones`
- 保存调 `adminApi.updatePdt`,沿用现有 pdt 写端点(数据字段名 `milestones` 保持不变);无独立 API 新增

**禁止**:本页不允许再用旧的"跳后台改结构"路径;`AdminPanel` / `ConfigTree` 已整体下线,任何新增结构编辑入口必须挂在本页工具栏或 LTC 主页工具栏,严禁恢复树状导航

## 4. LTC 主页

### 4.1 布局

整体 grid:`240px 1fr`,高度 `100vh`(扣顶栏)。

**左栏 `LtcTree.vue`**(固定宽 240px,内部纵向滚动):
- PDT 节点:展示 PDT.name,点击 `pushView({view:'pdt'})`,不可展开
- LTC 列表:按 `order` 升序;每项展示 `name` + 右侧模块数(template + 自有)chip;当前 LTC 高亮 `active`
- 点击 LTC:`pushView({view:'ltc', id})`,右栏整列重新渲染并滚动复位

**右栏(纵向滚动主区)**,从上到下:
1. **LtcHeader**:当前 LTC 名 + 周日期 + 红/黄/绿计数 chip + `StatusLegend` + **管理 toolbar**(仅 `canEnterLtcAdmin` 可见,排在 header 右端)
   - `⚙ LTC 配置` → Modal 包 `<LtcDrawer :ltc-id>`(编辑 LTC 名 / 归档 + 本 LTC 模块清单的新建与跳转);点击模块列表中的某行触发 `pick-module` → LtcMain 打开二级 Modal `<ModuleDrawer :module-id>`
   - `📸 快照` → Modal 包 `<SnapshotPanel>`
2. **TimelineBar**:传 `currentLtc.milestones`(LTC 自有里程碑);空数组时渲染占位条,引导从「⚙ LTC 基础」补充
3. **看板/风险区** **必须使用** `ltc/LtcCategoryGrid.vue`(LTC 唯一实现,内部封装看板/风险/子项编辑,与 PDT 的 `ModuleCardGrid.vue` 严格解耦)。
   - 数据源 = `ltcVisibleModules(currentLtcId)`,**仅返回 `scope=ltc & ltc_id=本LTC` 的副本**(模板模块经 `init-from-template` 拷贝后才进入 LTC 视图,详见 `04 §5.5`)
   - 三级结构:`Category(列) → Module(模块卡) → Sub-item(色块)`;列布局**最多 3 列**,大类数 >3 时折行(贴近设计稿)
   - 每个模块卡头部右上角显示 `Owner · xxx`(来自 `module.owner_open_id`,通过通讯录解析显示名)
   - Sub-item 按 `module_status.sub_items_color` 着绿/黄/红;未填态为灰
   - **看板段与风险段同卡**:风险并入每张 `LtcModuleCard` 内部(色块在上、风险说明紧跟在下),**不再有页面底部独立的风险区**
   - 「看板/风险」由 `LtcMain` 顶部双 chip 开关切换 `board` / `risk` / `both`(至少保留一个),控制的是**卡内两段的显隐**:`board`=只留色块行,`risk`=只留风险文字行,`both`=两段堆叠

### 4.2 主信息

- 模块卡(`LtcModuleCard.vue`,单卡承载两段,由 `showBoard` / `showRisk` props 控制显隐):
  - **卡头**:模块色头(`module_color` 决定背景) + 右上 `Owner · xxx` + 右上 `⚙` 结构编辑入口
  - **看板段**(`showBoard`):sub_items 色块网格 + 末尾 `+ 子项` 创建 tile(canEdit 时)
  - **风险段**(`showRisk`):模块级风险(`risksOf(entry)`,仅模块非绿时)+ 每个**非绿(红/黄)子项**一行(小色块 chip 可点编辑 + `sub_items_risk` 文案);全绿模块风险段留空(整卡仍展示,布局稳定)
- 列尾 `+ 新模块` tile:本 LTC Admin 可在该大类下直接新建 `scope=ltc` 模块(默认无 sub、无 KPI、无 Owner,后续可改)

### 4.3 数据派生与状态键

- `ltcVisibleModules(ltcId)` 返回该 LTC 自有副本(`scope=ltc & ltc_id=ltcId`),按 `order` 升序,封装在 `useDashboard.js`;**不**再混入模板模块
- `statusKeyOf(module, ltcId)` 返回该 module 的 status key:LTC 主页路径走 `module.id`(`scope=ltc`);复合键 `<ltc_id>::<module.id>` 仍保留用于其他可能的模板态共享场景
- `groupedForLtc(ltcId, modules)`(`useCategories.js`)按 `category_id` 把模块挂到 `scope=ltc & ltc_id=ltcId` 的大类下;无大类副本的 LTC 会落到「未分类」虚拟组(运维信号:需手动 `init-from-template`)

### 4.4 编辑入口

LTC 主页采用「就地编辑 + ⚙ 进详情」的双层节奏,凡是 status / 结构都不必绕外层抽屉。

**编辑模式开关(默认关闭)**:下表所有就地编辑入口(sub chip 可点、模块头可点、`⚙`、`+ 子项`、`+ 新模块`)**仅在编辑模式开启后才出现**。顶部 toolbar 的 `✏️ 编辑` 按钮(仅 `canEnterLtcAdmin && !isReadonly` 可见)切换开关;切换 LTC 自动退出编辑。纯查看态下卡片只读(色块不可点、无增删入口),避免误触。实现:`LtcMain.editMode` ANDed 进 `canEditStatusKey` 与 `canManageStructure`,再下传 `LtcCategoryGrid`。


| 操作目标 | 入口 | 实现组件 | 后端 |
|---------|------|---------|------|
| 改模块整体色 + 模块级 risk_note | 点模块头 | `ModuleStatusDialog.vue` | `PUT /api/status/<key>`(全量) |
| 改 sub-item 色 + 风险文字 | 点 sub chip | `SubItemEditDialog.vue` 编辑态 | `PUT /api/status/<key>`(全量) |
| 新增 sub-item | 点模块卡末尾「+ 子项」tile | `SubItemEditDialog.vue` 创建态 | `PUT /api/modules/<id>` 追加 sub + `PUT /api/status` 上色 |
| 删除 sub-item | 子项弹窗内「删除子项」按钮 | `SubItemEditDialog.vue` | `PUT /api/modules/<id>` 去 sub + `PUT /api/status` 清色/风险 |
| 改模块结构(名/Owner/sub_items/KPI) | 点模块头「⚙」 | `ModuleDrawer.vue`(经 LtcMain 转发) | `PUT /api/modules/<id>` 全量 |
| 新增本 LTC 模块 | 大类列尾「+ 新模块」tile | `LtcCategoryGrid.vue` 内联弹窗 | `POST /api/modules`(scope=ltc, ltc_id, category_id) |

**模板/副本权限**(LTC 主页只展示 `scope=ltc` 副本,模板池模块不出现在 LTC 主页):
- LTC Admin 对本 LTC 副本模块拥有**完整结构编辑权**(增删改名/Owner/sub_items/KPI/category_id),与模板已脱钩
- LTC Admin **不**直接编辑模板池(`scope=ltc_template`),模板由 PDT Admin / Super 在「⚙ 顶栏齿轮 → LTC 模板」中维护

历史周(`?week=...`)一律禁用所有编辑入口。

### 4.5 `?view=risks`(`risk` 别名)

- 命中同一 `LtcMain` 组件;风险已并入模块卡,**不再有独立 `#risk-section` 锚点**,无需 scrollIntoView
- 进入风险视图时顶部「风险」chip 高亮即可(卡内只留风险段);顶栏全局导航中不出现"风险详情"入口

## 6. 管理入口(原"管理后台"已退役)

> 原 `?view=admin` 的 `AdminPanel` + `ConfigTree` 树状形态已**整体下线**。下方为现行入口分布。

### 6.0 顶栏齿轮(⚙)

- 仅 Super / PDT Admin / 任一 LTC Admin 可见;点击打开 `PdtConfigDrawer`(`components/PdtConfigDrawer.vue`),右侧抽屉双 Tab
- **Tab 1「PDT 信息」**:
  - 编辑 `pdt.name`(沿用 `^[A-Za-z0-9_\-一-龥]+$` 校验);保存后顶栏品牌区即时更新
  - 编辑 `pdt.icon`(PDT 实例图标):预览缩略图 + 上传(`.svg`/`.png`,≤256KB)+ 清除;保存后顶栏 brand / favicon / `document.title` 一并刷新
- **Tab 2「LTC 模板」**(`components/admin/LtcTemplateEditor.vue`):
  - 单一模板池(全 PDT 共享),CRUD `scope=ltc_template` 的 Category / Module
  - 字段仅暴露 name / order / group;`sub_items` / `kpi_fields` / `owner_open_id` 不在模板里维护,新 LTC 拷贝后再补
  - 复用 `/api/categories`、`/api/modules` 端点(带 `scope=ltc_template` 参数),零新增写端点
  - 纯快照语义:改模板**不影响**已通过 `POST /api/ltc/{ltc_id}/init-from-template` 拷贝出去的 LTC 副本
- 不再承载 LTC 实例 / 模块实例 / 人员 / 快照入口(下沉到看板就地工具栏)

**图标渲染**(`App.vue` 顶栏 brand 区 + 运行时 favicon 注入):
- 顶栏:`pdt.icon` 非空时 `<img>` 渲染,28×28 圆角 6px;空时回退 `📊`
- favicon:`utils/favicon.js::setFavicon(url)` 在 PDT 配置加载/更新后动态写 `<link rel="icon">`;清除时移除该 link
- `document.title`:同步为 `${pdt.name} · PMD 项目看板`;PDT 未加载时回退 `PMD · 产品线项目看板`
- 资源 URL:`pdt.icon` 是 `assets/...` 相对路径,前端拼成 `/assets/<path>`,由后端只读静态路由提供(见 `11 §xx`)

### 6.2 各抽屉编辑入口与展示主信息

**MilestonesDrawer / MilestoneEditor**
- 必显字段:`milestones[]`(label/date/type/note + 上移/下移/删除)
- 编辑入口:行内 input + 时间轴预览,「+ 新增」「保存」按钮

**LtcDrawer**
- 必显字段:`name`(行内可改)、`order`、`archived`、本 LTC 模块清单
- 编辑入口:行内改名(失焦/回车提交)、归档/取消归档按钮、删除按钮(经 `ConfirmDialog`,有模块的 LTC 拒绝);「+ 添加模块」直接落入本 LTC,创建后 `emit('pick-module')`,LtcMain 打开 `ModuleDrawer` 二级 Modal

**ModuleDrawer**
- 必显字段:`group`、`name`、`owner`(用 `UserSearchInput`)、`sub_items[]`(name + id + owner_open_id + risk_note)、`kpi_fields[]`(key + label + unit + target)
- 编辑入口:行内 input 即时 PUT;子项/KPI 列表的「+」按钮添加;每项行右侧「×」删除

**SnapshotPanel**
- 必显字段:快照表(week / frozen_at / trigger / frozen_by)
- 编辑入口:「冻结本周」按钮;已存在时弹 `ConfirmDialog`,Super 可"强制覆盖",其他角色被告知无权
- 历史周点击 → 跳 `?view=pdt&week=YYYY-Www`(只读)

### 6.3 操作约束

- 所有删除操作必须经 `ConfirmDialog` 二次确认
- 删除模块前提示"将清除当前状态,历史保留"
- 删除 LTC 前若仍有关联模块:**直接拒绝**(`alert`),管理员需先归档或迁移模块
- Owner 修改实时生效,不需要被改 Owner 重新登录
- PDT 名称走 `PdtConfigDrawer` 的"草稿 + 保存";其余 LTC/Module 字段为"即时提交"
- 所有写操作完成后调用 `useDashboard.refresh()` 拉最新;SSE `config:reload` 也会自动触发其他端的刷新
- **禁止恢复** `AdminPanel` / `ConfigTree` / `PdtBaseDrawer` / `LtcsListDrawer`,新增结构编辑入口必须挂在 PdtOverview / LtcMain 的工具栏

## 7. 周次切换

- 入口:`SnapshotPanel`(从 PDT 总览 / LTC 进展 的「📸 快照」工具栏按钮进入)的快照表行内「查看」按钮
- **URL 是单一事实来源**:`?week=YYYY-Www`(校验形如 `2026-W21`)
  - `App.vue` 通过 `watch(current.week)` 同步到 `useDashboard.setWeek`,组件不直接调
  - 顶栏 nav 切换视图时(`nav()` / `pushView()`)必须保留 `current.week`,否则会意外退回当前周
  - `SnapshotPanel` 行内「查看」走 `pushView({ view: 'pdt', week })`,不要用裸 `<a href>` 重载页面
- 选历史周:`useDashboard.isReadonly=true`,顶栏出现黄色 banner「历史周(只读)· 所有编辑入口已禁用」
- `useEditableModules.editableSet` 在 `isReadonly` 下强制为空集,组件层自动隐藏 / 禁用编辑入口,无需各页重复判断
- SSE `snapshot:created`(冻结成功)触发 `SnapshotPanel` 自动刷新表格

## 9. 禁止项

- **禁止在 PDT 总览展示 LTC 子项色块**(那是 LTC 主页的职责;边界混淆会让卡片爆炸)
- **禁止在 LTC 看板段(色块行)展示风险说明全文**(色块只表达状态灯;风险全文在**同卡风险段**展示,由「风险」chip 控制显隐)
- **禁止给"未填报"赋色**(用灰色 `gray` 或显示"—",别用绿/黄/红混淆语义)
- **禁止历史周下出现可点击的编辑入口**(必须全部禁用或隐藏)
- **禁止在顶部全局导航中放"风险详情"按钮**(风险段内嵌在每张模块卡里,由 LTC 主页顶部「风险」chip 控制)
- **禁止把 PDT 里程碑叠加到 LTC 时间轴**(已在 `04` 明确解耦,不做"基线 + 高亮"展示)
- **【harness 红线】禁止 PDT/LTC 看板各自实现卡片**:
  - 模块卡片唯一实现 = `app/frontend/src/components/ModuleCardGrid.vue`
  - 风险任务卡片唯一实现 = `app/frontend/src/components/ModuleRiskList.vue`
  - 任何外层页面(`PdtOverview.vue` / `LtcMain.vue` / 未来新增看板)**不允许**内嵌写卡片 HTML/CSS,差异只能通过 props(`ltcId` / `canEnterAdmin` / `createDefaults` / `templateBadge` / `statusKeyOf` / `emptyHint`)表达
  - 违反 → PR 拒收
