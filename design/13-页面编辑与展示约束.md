# 页面编辑与展示约束

## 1. 模块目标

定义四类正式页面的展示主信息、编辑入口、跳转关系,确保管理者一眼可读、Owner 一键可填、风险一处可下钻。

## 2. 页面清单

| 页面 | 视图标识 | 主用户 | 数据来源 |
|------|---------|--------|---------|
| PDT 总览 | `?view=pdt` | 管理者(全员可看) | scope=pdt 模块 + pdt.milestones |
| LTC 主页 | `?view=ltc&id=<ltc_id>` | LTC Admin / Owner / 管理者 | scope=ltc_template ∪ (scope=ltc & ltc_id=当前) + `ltcs[i].milestones` |
| LTC 主页 · 风险区锚点 | `?view=risks&id=<ltc_id>`(`risk` 别名) | 管理者 / 评审会议 | 同上,载入 LTC 主页后自动滚动到 `#risk-section` |

> **LTC 主页是单页面**:左侧 PDT→LTC 树常驻,右侧单列上下滚,从上到下依次为 LTC 里程碑时间轴、看板区(全部模块)、风险详情区(只渲染非绿模块)。`?view=risks` 不再渲染独立组件,而是定位到同一页面的风险区锚点。
| 管理后台 | `?view=admin` | Super / PDT Admin / LTC Admin | 全配置 |

### 2.1 URL 参数约定

- LTC 实体 id 统一走 `?id=<ltc_id>`;旧链接 `?ltc=<ltc_id>` 由 `useView.js` 兼容解析
- `?view=risk`(单数)是 `?view=risks`(复数)的别名,在 `useView.js::VIEW_ALIAS` 注册;两者等价。两者均渲染 `LtcMain.vue`,后者额外携带 `scrollTo='risk-section'` 行为
- 未知 `view` 值回退到 `pdt`(默认视图)
- `?sub=timeline|kanban` 是 PDT 总览页的二级 tab;缺省 / 未知值回退到 `timeline`(其他页忽略该参数)

## 3. PDT 总览

### 3.1 布局(对应 `datas/screenshot-20260522-194954.png`)

- **顶栏品牌名**:左上 logo 文字 = `pdt.name`(动态),未加载到 PDT 时回退到字符串 `PMD`
- **页头**:仅展示 `StatusLegend`;PDT 名已迁移至顶栏,周次切换走顶栏 `WeekSwitcher`,本页不重复展示
- **二级 Tab**:`甘特图` / `全局看板` 两个并列按钮,通过 `?sub=timeline|kanban` 在 `useView.js` 内驱动;默认值 `timeline`。`甘特图` 视图渲染 `TimelineBar`,`全局看板` 视图渲染 PDT 卡片网格(含空态提示)。两个视图同一时间只显示一个
- **甘特图视图**:`TimelineBar`,横向时间轴,基于 `vis-timeline`(MIT,直接引入,不再自研几何排版)
  - 数据源:`pdt.milestones`;按 `date` 升序
  - 顶部为日期轴(年/月双层),下方按 `type` 分行(每个出现的 type 占一行,如 TR/SOP/OTA/目标/...)
  - 每个里程碑渲染为「形状 + 名字 + 月日」:形状/颜色来自 `04-PDT与LTC管理规范.md` 的 type 约定表;未列类型降级灰色圆点
  - 同行同日期自动错位堆叠,无须前端手算
  - 自带「今天」竖线、鼠标滚轮缩放、拖动平移;默认窗口覆盖最早→最晚里程碑 + 左右各 8% 留白
  - XSS 防护:vis-timeline 默认过滤 HTML 属性,自定义内容必须用 `template` 函数返回 DOM 元素,**严禁拼字符串带 class/style**
- **全局看板视图**:scope=pdt 模块按 `group` 分组,每组若干卡片;一行 4 列响应式
- 每卡片:
  - 标题:模块名 + 整体状态灯(`module_color`)
  - 状态灯 dots 顺序为 **绿-黄-红**(左→右,green-yellow-red),由 `ModuleStatusDots` 统一控制
  - "KPI" 与 "重点问题" 两个区段标题**恒显**,空数据时显示 "暂无" 灰字占位
  - 主体:`kpi_values` 逐项显示(label: value)
  - 底部:风险说明摘要(若非绿)+ Owner 名 + 最近更新时间
- 卡片右上角:edit 图标(仅 Owner/PDT Admin 可见),点击进入 StatusCell 编辑
- **视觉风格(样板 B · Report 体)**:
  - 标题字体使用衬线(`Source Han Serif SC / Songti SC` fallback),17px、Semibold、字距 1px
  - 卡头与卡脚使用 `1px solid var(--text)` 实线分隔(汇报体)
  - 区段标签双语:左侧 `KPI` / `ISSUES · N` 小写大写英文(letter-spacing 3px),右侧 `关键指标` / `重点问题` 衬线中文(letter-spacing 4px),下方 `1px solid var(--border-subtle)`
  - KPI 用 `<table>` 三列对齐:指标名(左) / 当前值(右对齐,16px、Semibold、tabular-nums) / 目标值(右对齐,11px、灰),行间 `1px dotted`
  - 重点问题用 `<ul>`,每行左侧 5px 小圆点指示 severity(灰/黄/红),行间 `1px dotted`
  - 数字与英文走 `font-feature-settings: 'tnum' on`,中文与衬线英文标题对比突显汇报物气质
  - 样板选样源文件:`doc/card-style-samples/sample-B-report.html`

### 3.2 主信息

- 必须显式展示的信息:模块名、状态灯、Owner、最近更新时间
- KPI 缺失时显示占位 "— —" 而非空白
- 风险说明截断 2 行 + "展开"

### 3.3 编辑入口

PDT 总览页采用"看 = 编"原则,所有 PDT 相关配置都在本页就地完成,不再跳后台。

**编辑弹窗 `StatusEditDialog` 的三块布局**(`PdtOverview` / `ModuleBoardGrid` / `ModuleRiskList` 三处共用):

1. **基本信息**(顶部高亮区)
   - 卡名 / 分组 / Owner —— 仅 `canEditStructure=true` 可改,否则只读展示
   - 整体状态灯(`module_color`)4 色 swatch —— 所有 `editable` 都能改
   - 「🗑 删除该卡」放在本块右下角,仅 `canEditStructure=true && mode==='edit'` 可见,走 ConfirmDialog → `DELETE /api/modules/{id}` → 本地 splice
2. **KPI** —— 表格三栏 `目标说明 / 现状 / 灯`
   - 每行 = 一个 `kpi_items[i]`,字段 `{label, value, color}`(target 字段后端保留兼容,UI 不暴露)
   - 灯下拉:— / 🟢 绿 / 🟡 黄 / 🔴 红
   - 增删行控件:仅 `canEditStructure=true`(Owner 只能改值不能改行数)
3. **风险/重点问题** —— 列表
   - 每行一个 `<textarea>`,**弹窗里不再有 severity 下拉**;新增风险统一 `severity='red'`,看板正面圆点渲染按 severity 着色仍兼容旧数据
   - 「+ 风险」按钮在块标题右侧
   - 非绿(整体或子项)时必填至少一条(`riskMissing` 校验)

**子项色块**(`sub_items`)在有子项的模块上额外渲染于"基本信息"与"KPI"之间;PDT 总览卡通常 `sub_items=[]` 不显示,主要在 LTC 模板/自有模块上出现。

**一键保存**:弹窗底部单按钮:
- `mode='edit'`:`保存` —— 一次性提交;status 字段走 `PUT /api/status/{id}`,structure 字段(name/group/owner)若 `canEditStructure=true && dirty` 同步走 `PUT /api/modules/{id}` 并本地原位替换 `modules[idx]`
- `mode='create'`:`创建` —— 只校验卡名非空,`POST /api/modules` 后 push 进本地 `modules`

**权限分层**(镜像后端 `can_edit_module_status` 与 PDT Admin 判定):

- `editable`(Owner / PDT Admin / Super):可改 整体灯 / KPI 行的"现状"和"灯" / 风险列表;入口由前端 composable `useEditableModules` 决定
- `canEditStructure`(仅 Super / PDT Admin):额外可改 卡名 / 分组 / Owner;可增删 KPI 行;可删除该卡
- 历史周(`useDashboard.isReadonly=true`)下 `editableSet` 强制清空,所有入口隐藏/禁用
- 422 inline 渲染在弹窗错误条;403 用弹窗内 toast 提示「无权编辑此模块」

**新增卡片**(仅 Super / PDT Admin 可见):

- 看板网格末尾追加一张虚线「+ 新增卡片」占位卡(`.add-card`),与其他卡同尺寸
- 点击复用 `StatusEditDialog` 的 `mode='create'` 形态,只渲染基本信息块;提交后 `POST /api/modules`(scope=pdt),返回后 push 进本地 `modules`

**顶部工具区**(`.head` 右侧,仅 Super / PDT Admin 可见,只读周隐藏):

- 「⚙ PDT 基础」→ Modal 包 `PdtBaseDrawer`
- 「👥 人员」→ Modal 包 `AdminUsers`
- 「📸 快照」→ Modal 包 `SnapshotPanel`

**里程碑编辑**(甘特图 tab 内联):

- `?sub=timeline` 时,`TimelineBar` 下方追加 `MilestoneEditor`(`show-preview=false`),仅 Super / PDT Admin 可见,只读周隐藏
- 保存调 `adminApi.updatePdt`,沿用现有里程碑端点;无独立 API 新增

**禁止**:本页不允许再用旧的"跳后台改结构"路径(顶栏齿轮的 `AdminPanel` 仅保留 LTC / 人员 / 快照入口,待 LTC 独立后整体下线)

## 4. LTC 主页

### 4.1 布局

整体 grid:`240px 1fr`,高度 `100vh`(扣顶栏)。

**左栏 `LtcTree.vue`**(固定宽 240px,内部纵向滚动):
- PDT 节点:展示 PDT.name,点击 `pushView({view:'pdt'})`,不可展开
- LTC 列表:按 `order` 升序;每项展示 `name` + 右侧模块数(template + 自有)chip;当前 LTC 高亮 `active`
- 点击 LTC:`pushView({view:'ltc', id})`,右栏整列重新渲染并滚动复位

**右栏(纵向滚动主区)**,从上到下:
1. **LtcHeader**:当前 LTC 名 + 周次切换器(复用 `WeekSwitcher`) + 风险数 chip(红/黄/绿计数)
2. **TimelineBar**:传 `currentLtc.milestones`(LTC 自有里程碑);空数组时渲染"该 LTC 暂无里程碑"占位条
3. **看板区 `<section id="board-section">`**:`ModuleBoardGrid`,模块列表 = `scope=ltc_template ∪ (scope=ltc & ltc_id=当前)`,按 `group` 字段分列(经典三列),每个模块按 `ModuleCard` 渲染:
   - 标题:模块名(右上 owner 头像);若 `scope=ltc_template` 加灰色 chip「模板」区分
   - 子项色块网格:每个 `sub_items[]` 一个 `StatusCell`,3–4 列
   - 无 `sub_items` 时中央显示一个大整体灯
   - 颜色不一致提示:`module_color=green` 但子项有非绿 → 标题旁黄三角警告
4. **风险区 `<section id="risk-section">`**:`ModuleRiskList`,**与看板区使用同一份模块清单**,但只渲染:
   - 整体灯非绿的模块,或
   - 至少一个子项非绿的模块

   按 `group` 1:1 对称分列,每个保留子项色块下展开 `risk_note` 完整文字(`StatusCell expanded=true`)。完全无风险的列保留列头 + "本周无风险"占位。

### 4.2 主信息

- 看板区必显:模块名 / Owner / 子项色块 / 子项名(hover)
- 看板区**不**展示风险说明全文(下方风险区有)
- 风险区必显:模块名 / 子项色块 / 子项名 / 风险说明全文 / Owner / 最近更新时间

### 4.3 数据派生与状态键

- `ltcModules` = `modules.filter(m => m.scope === 'ltc_template' || (m.scope === 'ltc' && m.ltc_id === currentLtcId))`
- 每个模块对应的 status 取键规则:
  - `scope=ltc_template`:`status[\`${currentLtcId}::${m.id}\`]`
  - `scope=ltc`:`status[m.id]`
- 该派生函数封装在 `composables/useStatusHelpers.js`,统一供看板/风险两区调用,确保 1:1 对称

### 4.4 编辑入口

- 子项色块点击 → 打开 `StatusEditDialog`,弹窗内对应子项行 `focus` 高亮
- 整体灯点击 → 打开 `StatusEditDialog`,默认无 sub 聚焦
- 提交 PUT 时:`scope=ltc_template` 使用复合 key `<ltc_id>::<module.id>`,`scope=ltc` 使用平铺 key
- 权限判定走 `useEditableModules.canEdit(module.id, ltcId?)`:对模板模块,LTC Admin 可编辑当前 LTC 下任一模板模块的状态;Owner 规则不变(对 owner_open_id 匹配的模块,所有 LTC 实例均可编辑——或后续按需细化,本版本采纳前者)
- 历史周一律禁用
- 不在此页改 owner / 模块结构(改结构走管理后台)

### 4.5 `?view=risks` 锚点跳转

- 命中同一 `LtcMain` 组件;载入后通过 `nextTick` + `scrollIntoView({behavior:'smooth', block:'start'})` 定位到 `#risk-section`
- 浏览器后退/前进保留滚动到锚点的行为
- 顶栏全局导航中不出现"风险详情"入口

## 6. 管理后台

### 6.0 入口

- 顶栏右侧齿轮(⚙)图标按钮仅在用户为 Super / PDT Admin / 任一 LTC Admin 时可见;点击进入 `?view=admin`,在 admin 视图下该按钮高亮(`.active`)
- 管理入口不再占据主 nav 文字位置(参考 Oversea Projects 顶栏图标分组),与 `WeekSwitcher`、用户名同处右侧工具区,排在最右
- 访客与普通 Owner 看不到入口;手动访问 `?view=admin` 时,各 tab 按需禁用按钮(`disabled`)

### 6.1 五个 Tab

| Tab key | 组件 | 主功能 | 可见角色 |
|--------|------|--------|---------|
| `pdt` | `PdtForm` | PDT 名 / description / milestones 增删拖拽 | Super / PDT Admin |
| `ltcs` | `LtcList` | LTC 列表 + 改名 + 归档 + 拖拽改序 + 删除(空 LTC) | Super / PDT Admin |
| `modules` | `ModuleEditor` | 按作用域(PDT 级 / 各 LTC)切换 + 增删模块 + 改 group/name/owner + sub_items + kpi_fields | Super / PDT / LTC Admin(限本 LTC) |
| `admins` | `AdminUsers` | super/pdt/ltc 三类管理员名单维护(chip + UserSearchInput) | Super(改 super/pdt) + PDT Admin(改 ltc) |
| `snapshots` | `SnapshotPanel` | 列出快照 + 手动冻结本周 + 切换历史周查看链接 | Super / PDT Admin(force 仅 Super) |

### 6.2 编辑入口与展示主信息

**PdtForm**
- 必显字段:`name`、`description`、`milestones[]`(name/date/type/note);时间轴顺序由 date 决定(展示按升序),但 admin 内允许拖拽给出"管理顺序"
- 编辑入口:行内 input,顶部「保存修改」按钮(本地 draft 累积,一次性 PUT;无未保存变更时 disabled)

**LtcList**
- 必显字段:`name`(行内可改)、`order`、`archived` 标志
- 编辑入口:行内改名(失焦/回车提交)、归档/取消归档按钮、删除按钮(经 `ConfirmDialog`,有模块的 LTC 弹错误对话框拒绝)

**ModuleEditor**
- 作用域切换器:`PDT 级总览` / 每个 LTC 一项
- 必显字段:`group`、`name`、`owner`(用 `UserSearchInput`)、`sub_items[]`(name + id + 删除)、`kpi_fields[]`(key + label + hint + 删除)
- 编辑入口:行内 input 即时 PUT;子项/KPI 列表的「+」按钮添加;每项行右侧「×」删除
- 拖拽:模块整体支持拖拽改 order;子项与 KPI 字段当前不支持拖拽(仅靠 order 字段)

**AdminUsers**
- 必显字段:三类管理员的 chip 列表(显示 name + ×)、UserSearchInput 添加
- 编辑入口:搜人 → 选中即加;chip 上的 × 即时删除

**SnapshotPanel**
- 必显字段:快照表(week / frozen_at / trigger / frozen_by)
- 编辑入口:「冻结本周」按钮;已存在时弹 `ConfirmDialog`,Super 可"强制覆盖",其他角色被告知无权
- 历史周点击 → 跳 `?view=pdt&week=YYYY-Www`(只读)

### 6.3 操作约束

- 所有删除操作必须经 `ConfirmDialog` 二次确认
- 删除模块前提示"将清除当前状态,历史保留"
- 删除 LTC 前若仍有关联模块:**直接拒绝**(`alert`),管理员需先归档或迁移模块
- Owner 修改实时生效,不需要被改 Owner 重新登录
- 修改 PDT 信息用"草稿 + 一键保存"避免每个字段都触发后端写;其余 LTC/Module 字段为"即时提交"
- 所有写操作完成后调用 `useDashboard.refresh()` 拉最新;SSE `config:reload` 也会自动触发其他端的刷新

## 7. 周次切换

- `WeekSwitcher` 组件位于顶栏右侧,在所有视图(含管理后台)中常驻
- 选项:`当前(实时)` + 所有快照周(后端按 `frozen_at` 降序返回)
- **URL 是单一事实来源**:`?week=YYYY-Www`(校验形如 `2026-W21`)。
  - `App.vue` 通过 `watch(current.week)` 同步到 `useDashboard.setWeek`,组件不直接调
  - 顶栏 nav 切换视图时(`nav()` / `pushView()`)必须保留 `current.week`,否则会意外退回当前周
  - `SnapshotPanel` 行内「查看」走 `pushView({ view: 'pdt', week })`,不要用裸 `<a href>` 重载页面
- 选历史周:`useDashboard.isReadonly=true`,顶栏出现黄色 banner「历史周(只读)· 所有编辑入口已禁用」
- `useEditableModules.editableSet` 在 `isReadonly` 下强制为空集,组件层自动隐藏 / 禁用编辑入口,无需各页重复判断
- SSE `snapshot:created`(冻结成功)触发 `WeekSwitcher` 与 `SnapshotPanel` 自动刷新下拉与表格

## 8. 执行约束

- 新增页面时:本约束先添一节,再在 `App.vue` 添视图,再写组件
- 改"必显示信息"或"编辑入口"前先改本约束
- 任意写操作必须经 `useDashboard` 或 `api/client.js`,严禁组件内直接 fetch

## 9. 禁止项

- **禁止在 PDT 总览展示 LTC 子项色块**(那是 LTC 主页的职责;边界混淆会让卡片爆炸)
- **禁止在 LTC 主页看板区展示风险说明全文**(只在同页风险区展开;看板区保持高密度俯视图)
- **禁止给"未填报"赋色**(用灰色 `gray` 或显示"—",别用绿/黄/红混淆语义)
- **禁止历史周下出现可点击的编辑入口**(必须全部禁用或隐藏)
- **禁止在顶部全局导航中放"风险详情"按钮**(风险区是 LTC 主页内嵌锚点)
- **禁止把 PDT 里程碑叠加到 LTC 时间轴**(已在 `04` 明确解耦,不做"基线 + 高亮"展示)
