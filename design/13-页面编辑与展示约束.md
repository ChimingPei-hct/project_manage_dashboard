# 页面编辑与展示约束

## 1. 模块目标

定义四类正式页面的展示主信息、编辑入口、跳转关系,确保管理者一眼可读、Owner 一键可填、风险一处可下钻。

## 2. 页面清单

| 页面 | 视图标识 | 主用户 | 数据来源 |
|------|---------|--------|---------|
| PDT 总览 | `?view=pdt` | 管理者(全员可看) | scope=pdt 模块 + pdt.milestones |
| LTC 研发进展 | `?view=ltc&id=<ltc_id>` | LTC Admin / Owner / 管理者 | scope=ltc 模块矩阵 |
| 风险详情 | `?view=risks&id=<ltc_id>` | 管理者 / 评审会议 | 上同,过滤非绿 |
| 管理后台 | `?view=admin` | Super / PDT Admin / LTC Admin | 全配置 |

### 2.1 URL 参数约定

- LTC 实体 id 统一走 `?id=<ltc_id>`(LtcProgress 与 RiskDetail 共用);旧链接 `?ltc=<ltc_id>` 由 `useView.js` 兼容解析
- `?view=risk`(单数)是 `?view=risks`(复数)的别名,在 `useView.js::VIEW_ALIAS` 注册;两者等价
- 未知 `view` 值回退到 `pdt`(默认视图)

## 3. PDT 总览

### 3.1 布局(对应 `datas/screenshot-20260522-194954.png`)

- **顶部 1 行**:`TimelineBar`,横向时间轴,渲染 `pdt.milestones`;按 `date` 升序排列,垂直分组(里程碑名 + 日期)
- **下方网格**:scope=pdt 模块按 `group` 分组,每组若干卡片;一行 4 列响应式
- 每卡片:
  - 标题:模块名 + 整体状态灯(`module_color`)
  - 主体:`kpi_values` 逐项显示(label: value)
  - 底部:风险说明摘要(若非绿)+ Owner 名 + 最近更新时间
- 卡片右上角:edit 图标(仅 Owner/PDT Admin 可见),点击进入 StatusCell 编辑

### 3.2 主信息

- 必须显式展示的信息:模块名、状态灯、Owner、最近更新时间
- KPI 缺失时显示占位 "— —" 而非空白
- 风险说明截断 2 行 + "展开"

### 3.3 编辑入口

- 整体状态灯 / 风险说明 / KPI 值在 `can_edit_module_status` 通过时可编辑
- 实现:`StatusCell` 接收 `editable` prop;`editable=true` 时点击色块发 `edit` 事件 → 打开 `StatusEditDialog`。卡片底部额外渲染「编辑」文字按钮,语义等价
- 权限来源:前端 composable `useEditableModules`(镜像后端 `can_edit_module_status`),不在组件里手算
- 历史周(`useDashboard.isReadonly=true`)下 `editableSet` 强制清空,所有入口隐藏/禁用
- 弹窗内可同时改 `module_color` / 各 `sub_items_color` / 各 `kpi_values` / `risk_note`,一次性 `PUT /api/status/{module_id}`
- 422 inline 渲染在弹窗错误条;403 用弹窗内 toast 提示「无权编辑此模块」
- 不允许在本页改模块结构(改结构去管理后台)

## 4. LTC 研发进展

### 4.1 布局(对应 `datas/screenshot-20260522-195002.png`)

- **顶部 1 行**:LTC 名 + 切换 LTC 下拉 + 周次切换器 + 跳转"风险详情"按钮
- **下方 3 列**:按 scope=ltc 模块的 `group` 字段分列展示(经典三列:硬件/感知/规控,但具体列名来自配置)
- 每列内:模块卡片(`ModuleCard`),卡片内:
  - 标题:模块名(右上 owner 头像)
  - 子项色块网格:每个 `sub_items[]` 一个 `StatusCell`,3–4 列
  - 当模块无 `sub_items` 时,卡片中央显示一个大色块(整体灯)
- 颜色不一致提示:若 `module_color=green` 但子项有非绿 → 标题旁显示黄色三角警告

### 4.2 主信息

- 展示项:模块名 / Owner 头像 / 子项色块 / 子项名(hover 显示)
- 不展示风险说明(去风险详情页看)

### 4.3 编辑入口

- 子项色块点击 → 打开 `StatusEditDialog`,弹窗内对应子项行有 `focus` 高亮(`focusSubId` prop)
- 整体灯点击 → 打开 `StatusEditDialog`,默认无 sub 聚焦
- 权限判定走 `useEditableModules.canEdit(module.id)`;ltc-admin 可编辑该 LTC 下全部模块,owner 仅自己的模块
- 历史周一律禁用(`editable=false`),色块不响应点击
- 不在此页改 owner / 模块结构

## 5. 风险详情

### 5.1 布局(对应 `datas/screenshot-20260522-195010.png`)

- 顶部:LTC 名 + 周次切换 + "返回 LTC 进展"按钮
- 主体:与 LTC 进展页同样的 3 列布局,但**仅渲染**:
  - 整体灯非绿的模块
  - 至少一个子项非绿的模块
- 每个保留的子项色块下展开 `risk_note` 完整文字(`StatusCell expanded=true`)
- 完全无风险的列保留列头 + "本周无风险"占位

### 5.2 主信息

- 必显:模块名 / 子项名 / 色块 / 风险说明全文 / Owner / 最近更新时间
- 用于评审会议:适合大屏展示,字体相对更大

### 5.3 编辑入口

- 同 LTC 进展页:整体灯 / 子项色块点击 → `StatusEditDialog`;卡片 footer 额外渲染「编辑」按钮
- 评审会议场景:Owner 在评审现场可直接改色 + 补风险说明,保存后 SSE 推 `status:reload` 同屏刷新
- 历史周下:禁用编辑(`useEditableModules` 已统一处理)

## 6. 管理后台

### 6.0 入口

- 顶栏「管理」按钮仅在用户为 Super / PDT Admin / 任一 LTC Admin 时可见
- 访客与普通 Owner 看不到入口;手动访问 `?view=admin` 时,各 tab 按需禁用按钮(`disabled`)
- Super Admin 在**空实例**(`ltcs` 与 `modules` 均空)下,顶栏额外显示「+ 示例数据」按钮 → 调 `POST /api/seed/demo`

### 6.1 五个 Tab

| Tab key | 组件 | 主功能 | 可见角色 |
|--------|------|--------|---------|
| `pdt` | `PdtForm` | PDT 名 / description / milestones 增删拖拽 | Super / PDT Admin |
| `ltcs` | `LtcList` | LTC 列表 + 改名 + 归档 + 拖拽改序 + 删除(空 LTC) | Super / PDT Admin |
| `modules` | `ModuleEditor` | 按作用域(PDT 级 / 各 LTC)切换 + 增删模块 + 改 group/name/owner + sub_items + kpi_fields | Super / PDT / LTC Admin(限本 LTC) |
| `admins` | `AdminUsers` | super/pdt/ltc 三类管理员名单维护(chip + UserSearchInput) | Super(改 super/pdt) + PDT Admin(改 ltc) |
| `snapshots` | `SnapshotPanel` | 列出快照 + 手动冻结本周 + 切换历史周查看链接 | Super / PDT Admin(force 仅 Super) |

### 6.2 编辑入口与展示主信息

**PdtForm**
- 必显字段:`name`、`description`、`milestones[]`(name/date/type/note);时间轴顺序由 date 决定(展示按升序),但 admin 内允许拖拽给出"管理顺序"
- 编辑入口:行内 input,顶部「保存修改」按钮(本地 draft 累积,一次性 PUT;无未保存变更时 disabled)

**LtcList**
- 必显字段:`name`(行内可改)、`order`、`archived` 标志
- 编辑入口:行内改名(失焦/回车提交)、归档/取消归档按钮、删除按钮(经 `ConfirmDialog`,有模块的 LTC 弹错误对话框拒绝)

**ModuleEditor**
- 作用域切换器:`PDT 级总览` / 每个 LTC 一项
- 必显字段:`group`、`name`、`owner`(用 `UserSearchInput`)、`sub_items[]`(name + id + 删除)、`kpi_fields[]`(key + label + hint + 删除)
- 编辑入口:行内 input 即时 PUT;子项/KPI 列表的「+」按钮添加;每项行右侧「×」删除
- 拖拽:模块整体支持拖拽改 order;子项与 KPI 字段当前不支持拖拽(仅靠 order 字段)

**AdminUsers**
- 必显字段:三类管理员的 chip 列表(显示 name + ×)、UserSearchInput 添加
- 编辑入口:搜人 → 选中即加;chip 上的 × 即时删除

**SnapshotPanel**
- 必显字段:快照表(week / frozen_at / trigger / frozen_by)
- 编辑入口:「冻结本周」按钮;已存在时弹 `ConfirmDialog`,Super 可"强制覆盖",其他角色被告知无权
- 历史周点击 → 跳 `?view=pdt&week=YYYY-Www`(只读)

### 6.3 操作约束

- 所有删除操作必须经 `ConfirmDialog` 二次确认
- 删除模块前提示"将清除当前状态,历史保留"
- 删除 LTC 前若仍有关联模块:**直接拒绝**(`alert`),管理员需先归档或迁移模块
- Owner 修改实时生效,不需要被改 Owner 重新登录
- 修改 PDT 信息用"草稿 + 一键保存"避免每个字段都触发后端写;其余 LTC/Module 字段为"即时提交"
- 所有写操作完成后调用 `useDashboard.refresh()` 拉最新;SSE `config:reload` 也会自动触发其他端的刷新

## 7. 周次切换

- `WeekSwitcher` 组件位于顶栏右侧,在所有视图(含管理后台)中常驻
- 选项:`当前(实时)` + 所有快照周(后端按 `frozen_at` 降序返回)
- **URL 是单一事实来源**:`?week=YYYY-Www`(校验形如 `2026-W21`)。
  - `App.vue` 通过 `watch(current.week)` 同步到 `useDashboard.setWeek`,组件不直接调
  - 顶栏 nav 切换视图时(`nav()` / `pushView()`)必须保留 `current.week`,否则会意外退回当前周
  - `SnapshotPanel` 行内「查看」走 `pushView({ view: 'pdt', week })`,不要用裸 `<a href>` 重载页面
- 选历史周:`useDashboard.isReadonly=true`,顶栏出现黄色 banner「历史周(只读)· 所有编辑入口已禁用」
- `useEditableModules.editableSet` 在 `isReadonly` 下强制为空集,组件层自动隐藏 / 禁用编辑入口,无需各页重复判断
- SSE `snapshot:created`(冻结成功)触发 `WeekSwitcher` 与 `SnapshotPanel` 自动刷新下拉与表格

## 8. 执行约束

- 新增页面时:本约束先添一节,再在 `App.vue` 添视图,再写组件
- 改"必显示信息"或"编辑入口"前先改本约束
- 任意写操作必须经 `useDashboard` 或 `api/client.js`,严禁组件内直接 fetch

## 9. 禁止项

- **禁止在 PDT 总览展示 LTC 子项色块**(那是 LTC 进展页的职责;边界混淆会让卡片爆炸)
- **禁止在 LTC 进展页展示风险说明全文**(去风险详情页;LTC 进展页保持高密度俯视图)
- **禁止给"未填报"赋色**(用灰色 `gray` 或显示"—",别用绿/黄/红混淆语义)
- **禁止历史周下出现可点击的编辑入口**(必须全部禁用或隐藏)
