# AI 边界与系统演进约束

## 1. 模块目标

明确 AI(Claude 等)在本仓库可做与不可做的事,以及系统未来从"JSON 文件 + 单实例"演进到更大规模时的边界,避免 AI / 人工跨过红线导致数据/逻辑/部署不一致。

## 2. AI 操作边界

### 2.1 AI 可以做的

- 读 `design/` 所有约束文档,理解模块边界
- 在 main 分支:修改代码、修改 `design/*.md` 约束文档(必须先读 `01`)、新增/修改测试
- 在 data 分支 worktree:按用户指令修改 `design/*.json` 数据(必须读 `03-代码与数据分离约束.md` 确认目标分支)
- 跑测试、跑 lint、跑构建
- 通过 API 端点修改数据(走业务流程,经过校验与角色)
- 生成迁移脚本(放到 `design/migrations/`,文件名带日期与意图)

### 2.2 AI 必须先确认的

- **改任意 `design/` md 文档**:先读 `01-设计文档编写约束.md`
- **改任意业务代码**:先读相关 module 文档(对照 `CLAUDE.md` 路由表)
- **改任意 `design/*.json` 数据**:先确认是否在 data 分支 worktree;若 main 分支上动 = 立刻停手
- **新增写端点**:先在 `10` 矩阵添行,先在 `test_role_matrix.py` 加用例,再写实现

### 2.3 AI 不允许做的

- **绕过 API 直接编辑 `module_status.json`**(必须经业务流程保证双写、广播)
- **跨实例 / 跨 data 分支 cherry-pick 数据**
- **删除任何 `module_updates.jsonl` 行**
- **in-place 修改任何 `weekly_snapshots/*.json`**
- **改 `id` / `code` 类稳定标识**
- **在 main 分支写入真实数据**(违反 `03`)
- **跳过 `validate_data_files.py` 保存**
- **引入新框架(Pinia/Element/Tailwind/axios 等)**(违反 `12`)

## 3. 数据迁移规则

### 3.1 何时需要迁移

- 字段语义变更(如颜色枚举从 3 种扩到 4 种)
- 文件拆分(如 `module_updates.jsonl` 按月切分)
- 数据载体迁移(JSON → SQLite)

### 3.2 迁移脚本规范

- 放 `design/migrations/`
- 命名:`YYYY-MM-DD-<意图>.py`(如 `2026-06-01-add-status-color-gray.py`)
- 必须:
  - 可重入(再跑一次结果一致)
  - 干跑模式 `--dry-run`,打印将做的变更
  - 在 data 分支 worktree 上运行,不动 main
  - 跑完后追加一行 `module_updates.jsonl` 记录(`kind=migration`)
- 任何破坏性迁移(删字段、改语义)必须先备份当前 `design/` 完整快照到 `design/migrations/backups/`

## 4. 系统演进路径

### 4.1 v1 → v1.x(数据规模增长)

- 模块数过百:前端按 group 折叠 + 虚拟滚动
- 历史流过大:按月切分(详见 `08` 扩展方式)
- 快照过多:UI 只显示最近 26 周,旧的归档目录

### 4.2 v2(多 PDT 聚合)

- 超出单实例范围,**不在本仓库直接做**
- 思路:每 PDT 独立实例,新增聚合服务从各实例 `GET /api/pdt` 拉数据
- 本实例的数据契约保持不变,作为聚合层的数据源

### 4.3 v3(数据库化)

- 触发条件:并发写冲突明显、文件锁阻塞、JSON 解析成为瓶颈
- 思路:`DATABASE_URL` 替代 `DATA_DIR`,JSON 文件变迁移种子
- 文件 Schema 一一映射数据库表;不重新设计模型,只换载体
- 历史流变事件表,周快照变物化视图

### 4.4 v4(组件化拆分)

- `main.py` > 6000 行时考虑拆 routes/auth/io
- 前端组件库可考虑外抽到 `packages/ui`,但要避免重 UI 库化的 trap

## 5. 长期稳定的契约(不允许轻易变)

- 颜色三态(绿/黄/红)
- PDT/LTC/Module/Sub-item 的概念名
- 文件名 `pdt.json` / `ltcs.json` / `modules.json` / `module_status.json` / `module_updates.jsonl`
- ISO 周号格式 `YYYY-Www`
- Cookie 名 `pmd_token_<port>`
- 五类角色

变更上述任意项 = 系统级 breaking change,必须先开 RFC(写一份 `design/RFC-<title>.md` 给出迁移路径),用户批准后实施。

## 6. 禁止项

- **禁止在没读 `01` 的情况下改 `design/` 文档**
- **禁止在没读相应 module 约束的情况下改对应代码**
- **禁止把"v1 暂不做"的功能当作"以后不会做"** — 用 `TBD` 标记,扩展方式章节明确路径
- **禁止把"AI 临时实验"代码合到 main**(走 feature 分支)
- **禁止用 AI 自动批量改历史流或快照**
