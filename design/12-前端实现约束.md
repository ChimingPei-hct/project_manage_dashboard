# 前端实现约束

## 1. 模块目标

定义前端 Vue 3 实现的稳定技术栈、目录结构、UI 规范、状态管理、SSE 接入模式,确保:

- 不引入会反复变动的重 UI 框架,降低长期维护成本
- 每类页面的展示与编辑入口都可被 `13` 单独定义
- 视觉风格(色块、圆角、tooltip)在所有组件中一致

## 2. 技术栈

- Vue 3.4+(Composition API + `<script setup>`)
- Vite 5+
- **无 vue-router**:用 query string `?view=xxx&...` 切换视图
- **无 Pinia**:用 `composables/use*.js`(ref + computed)管理全局状态
- **无 UI 组件库**:全自研 CSS + scoped(对齐 oversea_projects)
- Vitest + @vue/test-utils(组件单测)

## 4. 视图路由

| `?view=` | 组件 | 说明 |
|---------|------|------|
| `pdt`(默认) | `PdtOverview.vue` | PDT 总览 |
| `ltc` + `&id=<ltc_id>` | `LtcProgress.vue` | LTC 研发进展 |
| `risks` + `&ltc=<ltc_id>` | `RiskDetail.vue` | LTC 风险详情 |
| `admin` | `AdminPanel.vue` | 管理后台 |

切视图 = `history.pushState`,`App.vue` 监听 `popstate` 重新渲染。

## 5. 全局状态

`composables/useDashboard.js`:

```js
const pdt = ref(null)
const ltcs = ref([])
const modules = ref([])
const status = ref({})
const week = ref(null)         // null = 当前;否则 "2026-W21" 历史周(只读)

async function refresh() { ... }    // 并发拉 4 个端点
function subscribeSSE() { ... }     // sseBus 监听 status:reload / config:reload
```

- 单例(模块顶层 ref,跨组件共享)
- `App.vue` 启动时 `refresh()` + `subscribeSSE()`
- 历史周切换:`week.value = "2026-W21"`,从 `/api/snapshots/{week}` 拉数据替换 pdt/ltcs/modules/status

## 6. SSE 接入

复用 oversea_projects `sseBus.js` 模式:

- 单例 EventSource,连接 `/api/events`
- 指数退避重连:1s → 2s → 4s → ... 封顶 60s;稳定 ≥10s 重置退避
- 事件分发到订阅者
- `status:reload` → `useDashboard.refresh()`
- `snapshot:created` → `useSnapshots.refresh()`

## 7. UI 规范

### 7.1 圆角

- **6px**:按钮、StatusCell、chip、徽章 (`border-radius: 6px`)
- **4px**:嵌套小徽章(chip 内的小标)
- **直角**:segmented 切换控件外框
- **严禁**:`border-radius: 50%`、`9999px`、与高度同量级的大圆角值导致椭圆/胶囊外观

### 7.2 状态色(全局唯一来源:`style.css` CSS 变量)

```css
:root {
  --status-green: #52c41a;
  --status-yellow: #faad14;
  --status-red: #f5222d;
  --status-gray: #d9d9d9;   /* 未填报 */
}
```

- 严禁组件内 hardcode 色值
- 状态色仅用于状态语义,不用于装饰

### 7.3 引导气泡(强制)

**每次新增有交互行为的 UI 元素(按钮、chip、icon、可点击区域),必须同步加 hover 引导气泡说明用途**。

- 用全局指令 `v-tooltip="文案"`(实现复用 oversea_projects `App.vue:894-961`)
- 文案规则:
  - 动词开头("点击切换 LTC"、"修改本模块状态"),不只写名词
  - 说"会发生什么",不只说"这是什么"
  - 一行内(≤30 字),长说明用 `title=""` 兜底
- 同行多图标按钮 → **每个都单独气泡**

### 7.4 StatusCell 通用组件

- props:`color`(green/yellow/red/gray)、`note`、`editable`、`expanded`
- `expanded=false`:仅色块,hover 气泡显示 owner + note
- `expanded=true`:色块下展开 note 多行文本(用于风险详情页)
- `editable=true`:点击进入编辑(仅当 `can_edit_module_status` 为 true)
- 编辑态:色选 + 风险说明 textarea + 取消/保存,Esc 取消

### 7.5 固定列 / sticky 元素

- 底色全状态不透明,避免 flex gap 透出
- 多按钮合并为单面板(对齐 oversea_projects 规范)

## 8. API 客户端

`api/client.js`:

- 统一 `fetch(url, { credentials: 'include', timeout: 10s })`
- 401 → 跳飞书登录
- 403 → toast 提示并刷新数据(可能是状态变化导致权限失效)
- 5xx → 重试 1 次后报错横幅
- 不引入 axios(对齐 oversea_projects)

## 9. 历史周只读

- `week.value !== null` 时:
  - 顶栏显示"历史周(只读)"banner
  - 所有 `StatusCell` 强制 `editable=false`
  - 管理后台入口隐藏
- 任何写操作即使前端漏拦,后端也会 403(双层保护)

## 10. 执行约束

- 改 UI 规范前先改本文件
- 新增页面 = 新增一个组件 + 在 `App.vue` 路由表添一项 + 同步 `13-页面编辑与展示约束.md`
- 新增可编辑元素必须有对应的写权限判定调用(`can_*` 由后端返回当前用户可编辑的模块 id 集合,前端用此判断)
- 严禁直接读 cookie 判断登录(走 `/api/auth/me`)

## 10.x 外部依赖白名单

下列外部 npm 包是经评估后允许引入的例外,新增依赖必须先更新本节:

| 包 | 用途 | 引入理由 |
|----|------|---------|
| `vue` | 框架 | 核心 |
| `vite`、`@vitejs/plugin-vue` | 构建 | 核心 |
| `vitest`、`@vue/test-utils`、`jsdom` | 测试 | 核心 |
| `pinyin-pro` | `UserSearchInput` 拼音/首字母匹配 | 与 oversea_projects 对齐;体积小;无其他可行方案能保证中文姓名搜索体验 |

引入任何不在此表的依赖前,须先在本表追加一行说明理由,并提交 design 文档变更。

## 11. 禁止项

- **禁止引入 Vue Router、Pinia、Element Plus、Ant Design Vue、Tailwind**(违背"轻 UI"原则,且偏离 oversea_projects 对齐)
- **禁止用 50% / 9999px / 大圆角制造胶囊形**
- **禁止 hardcode 状态色值**
- **禁止跳过 v-tooltip 直接 `title=""`**(`title` 体验差,只作为长说明兜底)
- **禁止在组件内直接 fetch**(走 `api/client.js`)
- **禁止把权限判定写在组件里硬编码**(从 composable 拿 `canEdit(moduleId)`)

## 12. 扩展方式

- 国际化:新增 `composables/useI18n.js` + 简单 key-value 字典;v1 中文为主
- 移动端:增加响应式断点;StatusCell 可考虑紧凑模式
- 拖拽改序:用原生 `draggable`,不引入 dnd 库
